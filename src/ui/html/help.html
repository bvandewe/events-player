Overview

The CloudEvents Player is a powerful tool for testing, monitoring, and analyzing CloudEvents in real-time.
It provides multiple views for visualizing event streams and comprehensive filtering capabilities.

Main Features

Events View

Real-time list of incoming CloudEvents with full details, search capabilities, and expandable event data.

Timeline View

Visualize event activity over time with customizable granularity and comprehensive statistics including peak rates and quiet periods.

Metrics Dashboard

Monitor event patterns with charts showing top event types, sources, activity trends, and distribution metrics.

Global Filters

Filter events across all views by time range, type, source, subject, and custom attributes. Filters sync automatically.

Event Generator

Generate and send test CloudEvents to configured gateways with customizable parameters, iterations, and delays.

Authentication & Authorization

Role-based access control with OAuth/OIDC integration. Different permissions for admin, operator, and user roles.

Connection Status

  • The connection to the backend is established and refreshed every 15s.
  • An event was received within the last 10s.
  • The connection to the backend is broken. Trying to re-establish it every 2s.

Storage System

The application uses a tiered storage architecture to balance performance and capacity:

Tier 1: Recent Events (Full Data)
  • Capacity: 5,000 most recent events
  • Contains: Complete CloudEvent objects with all fields and data payloads
  • Purpose: Enables viewing full event details in the Events view
  • Behavior: Automatically trims oldest events when capacity is reached
  • Storage: Browser IndexedDB (persisted across sessions)
Tier 2: Metadata (Index)
  • Capacity: 100,000 event metadata records
  • Contains: Lightweight summary (ID, timestamp, type, source, subject, data size)
  • Purpose: Powers charts, statistics, and visualizations efficiently
  • Behavior: Retains metadata even after full events are trimmed
  • Storage: Browser IndexedDB (persisted across sessions)

Why Two Tiers?
This design allows the dashboard and timeline to display historical trends across 100,000+ events while maintaining detailed access to the most recent 5,000. Without this approach, storing 100,000 full events would consume excessive browser storage and slow down visualizations.

Important Notes:

  • Storage is browser-specific and not synchronized across devices or browsers
  • Clearing browser data will reset all stored events
  • The "Total Received" counter may reset between sessions but stored events remain
